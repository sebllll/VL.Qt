## 1 Summary

The area is large and mostly well made: the reconciler, the command writer, interaction, Qml, shaders and resources have dense unit tests, and the SmokeTest drives the real QtNative with a simulated clock and pixel probes. The hot-path contract (no allocation per frame) is tested directly. What is missing is a net for exactly what the refactoring changes: **nothing in the area checks the node API** (node names, pins, defaults, categories: no test mentions `ProcessNode`, `Pin` or `Categories`), the 60 help patches are checked only by hand (`vl-patch-check.py` and `test-vl-patch-check.py` are not in the CI), and the SmokeTest has **no reference images**: it probes single pixels. The Stride layer (`QtRendererNode`, `QtTextureNode`, `QtTextureRenderer`, `SharedTextureScene`) has no automated test at all.

The five changes that matter most:

1. **Before the refactoring starts:** a checked-in snapshot of the node API, generated by reflection, plus a unit test that compares it (TEST-01), and the patch checker in the CI (TEST-02).
2. A small set of reference images and one recorded command trace per help-patch scene, replayed against QtNative (TEST-03, TEST-04): the end-to-end net for protocol and QtNative changes.
3. `RecordingSink` prints numeric type and property ids; every reconciler assertion breaks when the protocol is renumbered (TEST-05).
4. The test hooks (K6): about 30 duplicated `addWarning` constructors, 4 counters, 11 fake-client constructors, 29 `vlqt_test_*` exports that ship in the product DLL (TEST-07, TEST-08).
5. SmokeTest structure: sources linked by about 30 `Compile Include` lines instead of a project reference, a 490-line `Main` with 95 hand-written `Selected(...)` lines, and `Px`/`Near`/`IsBg` copied into 34 files (TEST-10 to TEST-12).

## 2 What works and must survive

- **Allocation tests as the performance contract.** `Allocations.Fewest` (`src/VL.Qt.Tests/Allocations.cs`) takes the fewest bytes of up to five attempts, so a runtime one-off does not fail but a real per-frame allocation does. Users: `ReconcilerPerfTests`, `ReconcilerStructureTests.SteadyState_1000Children_NoAllocations_Fast`, `ReconcilerPropertyTests` (about line 255), `ReconcilerSceneTests` (about line 525), `RectangleNodeTests.UnchangedInputs_SameInstance_NoAllocation`. These are the nets for the hot paths: `Reconciler.Update`, `CommandWriter` (Reset/EndFrame), the change detection in `ElementNodeCore`. A refactoring must keep every one green and must not weaken them.
- **Deterministic frames.** SmokeTest `Pump(n)` advances a simulated clock by 1/60 s per call (`Program.cs:71`) and calls `vlqt_driver_advance`; scenarios do not wait for wall-clock frames. Keep.
- **`PerfLimits`** (`src/VL.Qt.SmokeTest/PerfLimits.cs`): one place for time limits, factor by flag or environment, warn-only mode, calibration on Linux, an arm64 default. Functional checks stay outside. Keep, and use it as the model for TEST-09.
- **`ProtocolDrift`** compares `protocol.h` and `Protocol.cs` by name and value by reflection (`--drift`). It is the only guard of the hand-mirrored protocol: any protocol refactoring runs it first.
- **Process exit contract of the SmokeTest:** `tools/build.ps1` reads the lines `PASS `, `FAIL `, `WARN `, `SMOKE OK` and the exit code, and checks the log for the thread-mode line. Do not change these strings without changing `build.ps1`, `tools/test-linux.sh` and `.github/workflows/build.yml`.
- **Real-artifact smoke test.** The CI runs the SmokeTest against the trimmed runtime that goes into the package (`build.yml:425`). This is why the test exports are in the shipping DLL (see TEST-08).
- **One process, many scenarios.** The Qt application is created once per process and the render-thread count is fixed at the first scene (comment at `Program.cs`, "run it alone"). A one-scenario-per-process design is not an option without cost (Question 4).
- **Sanitizer workflow** (`.github/workflows/sanitizers.yml`): asan/tsan run of the resource scenarios on QtNative. The only C++-level check.

## 3 Findings

### TEST-01 Add a checked-in snapshot of the node API and a test that compares it
- **Kind:** tests
- **Severity:** must
- **Breaking:** no
- **Where:** `src/VL.Qt.Tests/` (no test mentions `ProcessNode`, `Pin`, `Categories`), `src/VL.Qt.Tests/RectangleNodeTests.cs:31-36`, `tools/vl_pin_catalog.py`
- **Finding:** The refactoring renames and reshapes nodes and pins, and nothing in the automated tests notices. The node tests call `Update(...)` with all arguments positional, and `RectangleNodeTests.Update` repeats the pin defaults by hand ("Pin defaults as declared on Update", line 30): the test passes explicit values, so it never sees a changed `[DefaultValue]`. A renamed node, a reordered pin, a changed default or a changed category goes through every test and breaks a patch. The only description of the API is `tools/vl_pin_catalog.py` (370 lines), which parses the C# sources with regular expressions and globs fixed paths (`src/VL.Qt/Nodes/**/*Node.cs`, `src/VL.Qt.Stride/*Node.cs`, line 21). It will mis-parse or miss nodes when the refactoring moves files or changes the signature style, and it has no checked-in expected output.
- **Proposal:** (a) A unit test `NodeApiSnapshotTests` in `src/VL.Qt.Tests/Api/` that reflects over `VL.Qt.dll`, `VL.Qt.Stride.dll` and `VL.Qt.Audio.dll` (the Stride and Audio assemblies via a small test project reference or a loaded path), reads every `[ProcessNode]` class and writes one line per node and pin: node name, category (as vvvv shows it), pin name, direction, type, default (from the `[DefaultValue]` or the C# default of the `Update` parameter), visibility, order; plus one line per public type that is imported (`[assembly: ImportAsIs]`). (b) The expected output is `src/VL.Qt.Tests/Api/node-api.txt`, sorted, one fact per line so that a Git diff reads as a rename list. (c) The test fails on any difference and prints the diff; `dotnet test --filter NodeApi -- NUnit.Update=true` is not available in NUnit, so use an environment variable `VLQT_UPDATE_SNAPSHOT=1` that rewrites the file. (d) Each refactoring issue that changes the API regenerates the file in the same commit; the diff is the checklist for the help patches. (e) Keep `vl_pin_catalog.py --json` as the cross-check until the refactoring is done (the patch checker depends on it, TEST-02), then make the patch checker read `node-api.txt`, so the repository has one description of the API instead of two.
- **Decided:** P6, F6, P19 → the snapshot covers the whole public surface, not only `[ProcessNode]` classes: every public type and every public member of `VL.Qt.dll`, `VL.Qt.Stride.dll` and `VL.Qt.Audio.dll` with the attributes vvvv reads (node name, category, pin name, default, visibility, smell), plus the fixed pin set of the nodes generated from shader and QML files by a run of the two node factories over a test file; pin names are written by the rule `tools/vl_pin_catalog.py` uses (`fillColor` → `Fill Color`) so that the migration script of P19 can work from the diff; the file is `src/VL.Qt.Tests/Api/node-api.txt` (test `NodeApiSnapshotTests`), written in full and regenerated by the author of each issue (F6); C2 of [DECISION-ROUND.md](../DECISION-ROUND.md) → once `node-api.txt` exists, `tools/vl-patch-check.py` reads it and `tools/vl_pin_catalog.py` goes, in an issue of wave 5
- **Effort:** M, mechanical: no
- **Touches:** new `src/VL.Qt.Tests/Api/NodeApiSnapshotTests.cs`, `node-api.txt`; later `tools/vl_pin_catalog.py`, `tools/vl-patch-check.py`
- **Depends on:** none (must exist before the first renaming issue)
- **Verification:** the test is green on develop; rename one pin and see the exact line in the failure message.

### TEST-02 Run the patch checker and its regression test in the CI
- **Kind:** tests
- **Severity:** should
- **Breaking:** no
- **Where:** `.github/workflows/build.yml` (no `vl-patch-check`, `vvvvc`, `test-vl-patch-check` step; only `test-nupkg-consumer.ps1` at line 413), `tools/vl-patch-check.py`, `tools/test-vl-patch-check.py`
- **Finding:** AGENTS.md calls the help patches "the test base", but no automatic run checks them. The checker needs only Python, no vvvv; it finds a link to a pin the node no longer has (`missing-pin`), the exact failure mode of a rename. It is run by hand, and `build.yml` ignores `help/**/*.vl` via `paths-ignore` (line 21), so a patch-only PR runs no check at all. `vvvvc` needs vvvv on the runner (the comment at `build.yml:406` says so), so that step cannot be a normal PR check.
- **Proposal:** Add a job `patches` (ubuntu, Python only): `python tools/test-vl-patch-check.py` and `python tools/vl-patch-check.py` with exit code; remove `help/**/*.vl` from `paths-ignore` for this job only (or give the job its own `on.paths`). During the refactoring the orchestrator also runs `tools/vvvvc.ps1` over all patches at the end of each phase (a loop script `tools/check-all-patches.ps1`, local, not CI), because the compile check is the only one that proves the patch still loads.
- **Decided:** P19, P16, P18, 'CI only by hand' → `vl-patch-check.py` and `vvvvc.ps1` are part of the gate of every issue (the patches stay compilable after every issue), not only at the end of a phase; a job in `build.yml` runs only at the checkpoints of P18 (when the standing draft PR `refactor` → `develop` is made ready), and pull requests against `refactor` start no CI
- **Effort:** S, mechanical: yes
- **Touches:** `.github/workflows/build.yml`, new `tools/check-all-patches.ps1`
- **Depends on:** none
- **Verification:** a PR that renames a pin without touching the patch fails the new job.

### TEST-03 Compare the grabbed PNGs with reference images
- **Kind:** tests
- **Severity:** should
- **Breaking:** no
- **Where:** `src/VL.Qt.SmokeTest/Program.cs:105-116` (`Grab`, `Px`, `Near` with tolerance 8), `ReadmeImagesTest.cs:62` and `ReadmeGalleryTest.cs` (`File.Copy(grabPath, target, true)` into `docs/images/`), `Program.cs:482` (`SameImage`, used for "unchanged" checks only)
- **Finding:** There is no baseline. Scenarios grab a window and probe a handful of pixels, for example `RectangleTest.cs:55-62`. That is robust against font and antialiasing differences, but a rendering change that moves anything else (a style, an effect, a layout offset, text) is not seen. The scenarios `readme-images` and `readme-gallery` already render the documented scenes (effect chains, styles, layout, images) and **overwrite** the checked-in `docs/images/*`, which are the best reference set the project has; the check that they still look the same is the git diff after a run, by hand.
- **Proposal:** Make `readme-images` and `readme-gallery` compare instead of copy by default: render to `outDir`, compare with `docs/images/<name>.png` by mean absolute difference per channel and a share of differing pixels (limits as `PerfLimits`-like constants in one `ImageCompare` helper in the SmokeTest), print `FAIL` with the path of the grab and a diff image; `--update-refs` keeps the old behaviour (copy). Scenes with text use the bundled font loaded by `LoadFont` (as `FontTest` does) or avoid text; references are valid for one backend (Question 2): compare only when the log says D3D11 on Windows, `SKIP` on the software backend, as `NeedsRhi` already does. Add 5 to 8 more scenes that the README does not show but the refactoring touches: Row/Column layout with anchors, a Shape with stroke and dash, a Slider and Button style, an Image with fill modes, a Group with opacity and clip.
- **Decided:** F3, P9 → the compare always runs on WARP (a switch that the issue names forces it), so the local gate and the CI see the same pixels, and the arm64 notebook does not `SKIP`; wave 1 first checks whether a local WARP run on the arm64 notebook and on the x64 workstation matches the x64 references within the tolerance, and a second set for win-arm64 is added if it does not; a reference changes only through `--update-refs`, run on the x64 workstation or taken from the CI artifact, committed on its own with the diff image in the pull request description
- **Effort:** M, mechanical: no
- **Touches:** `src/VL.Qt.SmokeTest/ReadmeImagesTest.cs`, `ReadmeGalleryTest.cs`, new `ImageCompare.cs`, `docs/images/`
- **Depends on:** TEST-12 (shared pixel helpers), Question 2
- **Verification:** change the radius default of `Rectangle` in a scratch build and see the gallery fail.

### TEST-05 `RecordingSink` prints numeric ids; name them
- **Kind:** tests
- **Severity:** should
- **Breaking:** no
- **Where:** `src/VL.Qt.Tests/RecordingSink.cs:37-60`, `ReconcilerStructureTests.cs:47-52,108,178`, about 225 assertions in `Reconciler*Tests`, `SinkRegistryTests`, `EffectChainReconcilerTests`
- **Finding:** Expectations read `"CREATE 1 1"`, `"CREATE 2 3"`, `"CREATE 3 7"`, `"SET 1 256 ..."`: element type and property are raw `ushort`. The reader cannot tell what type 7 is without `Protocol.cs`, and **any renumbering or reordering of the protocol (allowed by the decisions) breaks every assertion** although the behaviour is unchanged. The brief allows protocol changes, so this is a certain cost of the refactoring.
- **Proposal:** `RecordingSink` renders type and property by name from a table built once by reflection over `Protocol.Type` and `Protocol.Prop` (the same reflection `ProtocolDrift` already does): `CREATE 3 Rectangle`, `SET 3 Color color(1,0,0,1)`. Expectations are rewritten once by a script (search and replace of the number with the name using the table); after that a renumbering changes nothing. Where two names have the same value the sink prints the first and the table test (`ProtocolNamesAreUnique`) says so.
- **Decided:** A5, O7, A1, P4 → the names the sink prints are the ones after the break: protocol type `GROUP` (was `ITEM`) and `feedbackId` (was `sinkHandle`); the step of P4 that renames them also changes the expectation strings that contain them, mechanically with the same name table; `SinkRegistry*Tests` become `FeedbackRouter*Tests`
- **Effort:** M, mechanical: yes (the rewrite of the expectations is a script)
- **Touches:** `RecordingSink.cs`, about 12 reconciler and sink test files
- **Depends on:** none (do before the protocol issues)
- **Verification:** unit tests green; renumber one type id in a scratch build and run the reconciler tests: they stay green.
