# Decisions – refactor (release 0.10.0)

State of the discussion for the review and refactoring of VL.Qt before 1.0. Phase: **brainstorm** (no plan, no issues, no code changes yet). The review is finished: 23 reports with 340 findings, index in [review/README.md](review/README.md). Newest entries first in each section. Format: **Topic (who, date):** decision. Reason.

## Decided

- **Issues are packages, tasks are pull requests (Sebastian, 2026-11-20):** the cut has about 190 tasks; they go to GitHub as 30 issues, one per package (a wave-1 or wave-3 package, the cuts, the chain, one per lane of wave 4, tests, docs, release), each with its tasks as a task list. A task is one branch and one draft PR against `refactor`, merged with a merge commit, no squash ("erstmal alles normal mergen", Sebastian, 2026-11-20), `Part of #<issue>`; the issue closes with its last task. This refines "One branch and one draft PR per issue". [ISSUES.md](ISSUES.md) section 2a.

- **Open catalog and shader rows decided (Sebastian, 2026-11-19):** blocks D and E of [DECISION-ROUND.md](DECISION-ROUND.md), all as recommended; the decisions are in the Decision columns of [review/23_api.md](review/23_api.md) section 7 and of [review/28_shader-reference.md](review/28_shader-reference.md). Notable: QtTexture loses its empty `Perf` pin; `TouchPoint` becomes a struct; QML `point`/`size` reach the patch as `Vector2`; reserved uniform names are an error at the node; path start points follow Skia; every effect node gets an optional `Apply` (default true, last input pin); ColorAdjust `Saturation` takes HSCB's scale (1 = unchanged, default 0 = grey), so a patch with the same value looks different; every effect length default moves from units to DIP at 1 unit = 100 DIP; element shaders get `texelSize`, `dpr` and `viewSize`; shader files get `@optional`, `@tags`, `@remarks` and relative `@category`.

- **Smaller rules from the decision round (Sebastian, 2026-11-19):** block C of [DECISION-ROUND.md](DECISION-ROUND.md), all as recommended. The options of the custom SmokeTest runner become unit tests, NUnit filters or explicit tests (C1); "over budget" compares Qt work with vvvv's frame interval, one budget (C4); the six style process nodes are `SetColorsNode` … `MergeNode` in `Nodes/Style/`, the static style nodes stay in `Styles/` (C13); the reconciler, input and effect-internals pages are design notes in `docs/design/` (C14); QML type files keep PascalCase, a named exception of S2 (C16). The other points of block C are recorded at their findings.

- **The details of the native break (Sebastian, 2026-11-19):** block B of [DECISION-ROUND.md](DECISION-ROUND.md), all as recommended. One result table `vlqt_result` for every export, `poll` included (apply codes -2 … -8, `VLQT_ERR_NULL_HANDLE`, exceptions `VLQT_ERR_INTERNAL`); `vlqt_window_create` takes the position, `_create_at` goes; the version export is `vlqt_app_get_abi_version` with one number for protocol and C ABI; the log callback becomes a function pointer in the same pull request; `Driver::setTime` ignores a time below the current one; a value above the sanity cap fails the reconcile, nothing is truncated; the protocol says `BeginEffectChainLink`/`EffectChainLink`; only `Protocol.ElementType` exists (`Elements/ElementType.cs` goes); the shader element side is `ShaderLayout`, `ShaderDescription`, `ShaderInstance`; `ShaderPadding` has no unit flag; a cut is a pure move first, and the order of [TARGET.md](TARGET.md) 3.3 binds.

- **The merged effects take DIP too (Sebastian, 2026-11-19):** "Shaders follow VL.Stride" (E1) covers every length of an effect, also the values of Qt's MultiEffect: DropShadow `Offset` and the `Padding` of Blur and DropShadow are in DIP like the lengths of the shader effects, so one chain never mixes units. A5 in [DECISION-ROUND.md](DECISION-ROUND.md).
- **Effect pin names follow VL.Skia, shader files follow TextureFX (Sebastian, 2026-11-19):** where VL.Skia has the node or pin, its name wins (Blur `Amount`, DropShadow `Offset` as `Vector2`, `Blend Mode`), by A7; TextureFX is the reference for units and the conventions of shader files (E1). A4 in [DECISION-ROUND.md](DECISION-ROUND.md).
- **The generated nodes lose `Error` too (Sebastian, 2026-11-19):** "No `Error` output pins" also holds for the nodes generated from QML and shader files; their errors go to the log and mark the node. The switch `Warn | ErrorPin` of SHD-09 goes, and `Error` is no reserved pin name. A3 in [DECISION-ROUND.md](DECISION-ROUND.md).
- **One mechanism for messages at a node (Sebastian, 2026-11-19):** `NodeErrors` is the one store, with one entry per phase, so warnings and errors no longer overwrite each other (RUN-01); `NodeMessage` is the handle one message source holds on it (NODE-05); `ResourceNodeReport` and the shader area use it. A test seam `INodeMessages` comes only if a test cannot observe the warning through `NodeContext.Create` (TEST-07). VideoSourceToQtImage marks its node on a lasting error like ToQtImage. A1 in [DECISION-ROUND.md](DECISION-ROUND.md).

- **QtNative gets one folder per area and snake_case file names (Sebastian, 2026-11-19):** `src/VL.Qt.Native` is cut into the folders of [TARGET.md](TARGET.md) section 2.3 (`app/`, `window/`, `scene/`, `elements/`, `effects/`, `resources/`, `device/`, `offscreen/`, `diagnostics/`, `test/` …); `vlqt.h`, `vlqt_test.h`, `protocol.h` and `wire.h` stay at the top. Every file name is snake_case. A folder is created by the cut that fills it. Reason: each report saw 10 to 25 files and most stayed flat, but merged the layer has about 150 files instead of 51, and the names were mixed. S2 in [TARGET.md](TARGET.md).
- **Namespaces follow the categories, folders follow the reader (Sebastian, 2026-11-19):** a public type that is not a node sits in the namespace of its category (`VL.Qt.Elements` → `Qt.Elements`), or says it with `[Category]` where the namespace cannot carry it. A folder directly under a project has one namespace, and its subfolders share it. All node classes are `VL.Qt.Nodes`, since nodes set their category themselves; `Nodes/Paths/` moves there (NODX-11). `Runtime/`, `Scene/` and `Window/` stay `VL.Qt`. Reason: the category is what a user sees and the catalog has decided it; a finer namespace for internal types only adds `using` lines, and VL.Skia keeps almost everything in `VL.Skia` too. The issue of API-01 checks in vvvv that node categories stay absolute. S1 in [TARGET.md](TARGET.md).
- **The code follows the node `Shader`; `ShaderEffect` becomes the effect (Sebastian, 2026-11-19):** after C14 the element is `Shader` in every layer (`Shader`, `ShaderNode`, `VLQT_ELEMENT_TYPE_SHADER`, `ShaderItem`). An effect of a chain that runs one shader is `ShaderEffect`, next to `BlurEffect` (was `ShaderLink`). "Link" is left to vvvv's links and to one entry of a chain as it is sent. Reason: everything named `…Effect` is then a step of the chain, in the code as in the node browser. Accepted: `ShaderEffect` means the element up to 0.9.10 and the effect from 0.10.0 on; the types are internal. O5 in [TARGET.md](TARGET.md).
- **"Node" means a vvvv node (Sebastian, 2026-11-19):** in C# only classes that are vvvv nodes end in `Node`; in C++ the word is left to Qt's scene-graph nodes (`QSGNode`). The reconciler's `Node` and `HandlerNode` become `ItemMirror` and `HandlerMirror` (REC-07), the ones of QtNative `ElementEntry` and `HandlerEntry`, and the helpers inside the node classes end in `…NodeCore` (`ElementNodeCore`, `InteractionNodeCore`). Reason: the word named five things, and AGENTS.md already reserves the suffix for nodes. O3 in [TARGET.md](TARGET.md).
- **"Scene" has the same four names in C++ and C# (Sebastian, 2026-11-19):** a scene is what one renderer owns on the Qt side, its elements and the window or offscreen texture they are drawn to. `SceneHandle` is what the C handle `vlqt_scene` points to, `Scene` the shared part, `WindowScene` and `OffscreenScene` the two kinds. The tree of the patch is the "element tree", never a scene, and the registry loses the word (`OccurrenceRegistry`, `InteractionRegistry`). Reason: the reports gave the word to six things and would have left two structs named `Scene` in QtNative. O2 in [TARGET.md](TARGET.md).
- **The node-API snapshot covers the whole public surface (Sebastian, 2026-11-19):** TEST-01 lists every public type and every public member of `VL.Qt.dll`, `VL.Qt.Stride.dll` and `VL.Qt.Audio.dll` with the attributes vvvv reads, plus the fixed pin set of the nodes generated from shader and QML files. Reason: vvvv also makes nodes from static methods and from the members of imported types (about 120 besides the 76 process nodes), and C5 renames about fifty of them. P6 in [PLAN-CHECK.md](PLAN-CHECK.md).
- **One target page before any rename (Sebastian, 2026-11-19):** `TARGET.md` is written before wave 3 and before the findings are reconciled: a glossary with one word per concept across C, C++, C#, the docs and the node names; the folder and namespace tree of the four projects, merged from section 4 of the reports; and which findings cut the same file. Reason: the reports claim the same words for different things ("scene" six times), and "feedback" (A1) already names the layer in QtNative that keeps the previous frame. The glossary is the page of DOC-09, so DOC-09 and DOC-10 move forward from wave 6. P3 in [PLAN-CHECK.md](PLAN-CHECK.md).
- **Findings are reconciled with the decisions before the issues are cut (Sebastian, 2026-11-19):** one session goes through all 23 reports and adds a line `Decided:` under the proposal of every finding that a decision changes or whose proposal branches on a question. Reason: the reports were written before the decisions, and an issue cut from such a finding would carry the wrong branch. The same pass appends every change of the node API that has no row yet to the catalog (section 7 of [review/23_api.md](review/23_api.md)), and the open rows are decided in one round afterwards. P1 and P2 in [PLAN-CHECK.md](PLAN-CHECK.md).
- **Catalog of node, pin and category changes decided (Sebastian, 2026-11-19):** every row of [review/23_api.md](review/23_api.md) section 7 has a decision. Deviations from the proposals: Uniform nodes keep their names (`Float` …) in `Qt.Elements.Shaders.Uniform`; `VideoSourceToQtImage` keeps its name, as VL.Video's `VideoSourceToSKImage`; DropShadow `Blur` becomes `Blur Amount`; RadialBlur `Angle` default `0.05` cycles; `ToTexturePixels` goes to `Stride.Input` next to `MouseRay`, not to `Stride.Textures.Source`; Font Weight is `int` everywhere (also on the Text node) and the enum `FontWeight` goes, since Qt and CSS take any weight 1–1000. Added during the review: `Size` optional on every node whose `Auto Size` is on by default (also containers and Shader), Pinch `Min Point Count`/`Max Point Count`, Labeled `Element` → `Input`. The user-facing element type stays `IElement`.
- **Semantic versioning, no version rule in the contributor pages (Sebastian, 2026-11-19):** VL.Qt follows semantic versioning (before 1.0 a minor release may break). AGENTS.md and CONTRIBUTING.md keep only "milestones are version numbers; `1.0` blocks the release" and drop "0.9.x until 1.0". Question G2 in [QUESTIONS.md](QUESTIONS.md).
- **SmokeTest becomes NUnit, first in wave 1 (Sebastian, 2026-11-19):** the custom runner goes; every scenario is an NUnit test with one Qt start per run, and the few scenarios that need a process of their own run a small helper executable from an NUnit test. `build.ps1 -Test` and the CI read NUnit results. Done first so that the new safety-net tests are written once, in the new project. Question F5 in [QUESTIONS.md](QUESTIONS.md).
- **No JavaScript in the QML of built-in elements (Sebastian, 2026-11-19):** logic of built-in elements is computed in QtNative (C++) or C#, not in JavaScript bindings of their QML; Row/Column alignment moves to C++ (NELM-13). User QML is not affected. Exception only if the move is a large rebuild, raised again then. Question E12 in [QUESTIONS.md](QUESTIONS.md).
- **Pins instead of environment variables (Sebastian, 2026-11-19):** whatever a patch may want to set is a pin, usually hidden. Environment variables stay only for what must be fixed before vvvv starts (Qt's own, such as `QT_LOGGING_RULES`) and for pure test switches (forced device loss, synthetic input). An issue goes through every `VLQT_*` variable and sorts it: `VLQT_IMG_UPLOAD` becomes the pin `Upload` (E10), `VLQT_OFFSCREEN_THREAD` the pin `Render Threads` with 0 for the main-thread mode (E6, E7). Raised with questions E7 and E10 in [QUESTIONS.md](QUESTIONS.md).
- **QtNative runs Qt's `basic` render loop, on purpose (Sebastian, 2026-11-19):** preparing and drawing a frame happen on one thread, in step with vvvv. This becomes one design note that every native area checks against; code that is cheap to make correct under the `threaded` loop too is written that way (NFX-03). Question E4 in [QUESTIONS.md](QUESTIONS.md).
- **Shaders follow VL.Stride and its TextureFX (Sebastian, 2026-11-19):** for every shader question (units, uniform and pin names, defaults, file conventions, sampler handling) the reference is VL.Stride, its shaders and TextureFX (`C:\vl\VL.StandardLibs\VL.Stride`). Shader parameters are in pixel space (DIP), not in the renderer's units or normalised, so a change of the renderer's space changes no shader parameter. Deviations are written down with their reason. The principle is about what a patch and a shader author see (names, units, conventions): a shader need not compute or look like its TextureFX counterpart. The comparison is a report of its own, `review/28_shader-reference.md` (P12 in [PLAN-CHECK.md](PLAN-CHECK.md)). Raised with question E1 in [QUESTIONS.md](QUESTIONS.md).
- **Qt private API is allowed (Sebastian, 2026-11-19):** QtNative may use Qt's private classes (no compatibility promise between Qt versions) wherever they help, also new ones. More work on a Qt update is accepted. The classes in use are listed in one place (head comment of `elements.h`) as the checklist for an update. Question D9 in [QUESTIONS.md](QUESTIONS.md).
- **Defaults explicit unless the type's default is meant (Sebastian, 2026-11-19):** AGENTS.md changes to "set a default explicitly unless `default(T)` is the intended value; never for `Matrix`", since vvvv's default of a `Matrix` pin is the identity (corrected with A2 of [DECISION-ROUND.md](DECISION-ROUND.md): this entry said "always", option (b) of D3 says "never"; Sebastian from memory, the issue of D3 checks it once in vvvv); the explicit zeros of the shape nodes go, `tools/vl_pin_catalog.py` reads a missing default as `default(T)`. Question D3 in [QUESTIONS.md](QUESTIONS.md).
- **No `Hidden` attribute on the `NodeContext` parameter (Sebastian, 2026-11-19):** the rule goes from AGENTS.md, the six existing attributes are removed; known finding K5 needs no issue of its own. Reason: vvvv hides the parameter by its type, and VL.StandardLibs writes it without the attribute (66 to 4). Question D2 in [QUESTIONS.md](QUESTIONS.md).
- **One element type on every input (Sebastian, 2026-11-19):** every input that takes an element accepts the same type (`IElement` today), also Renderer, Labeled, Snapshot and the effect inputs; the reconciler applies the base style where a stylable widget arrives. Outputs show the same type; `Element` becomes the internal base class; the name stays `IElement` (catalog). `IStylable.Build` returns `IElement?`, and a returned stylable is resolved in turn (P5 in [PLAN-CHECK.md](PLAN-CHECK.md)). Reason: one concept, one type name, as `ILayer` in VL.Skia. Question C3 in [QUESTIONS.md](QUESTIONS.md).
- **No `Error` output pins (Sebastian, 2026-11-19):** the `Error` string outputs go (today on LoadImage, LoadImage (Async), LoadFont, ToQtImage, VideoSourceToQtImage, Snapshot, both FileWriters, QmlElement, ShaderEffect, QtTexture, QtRenderer and the Renderer). Every error goes to the vvvv log; a lasting error (missing file, shader or QML that does not compile) also marks the node in the patch (warning or error with the message as tooltip). Where a patch must react, a plain state output stays (Snapshot `Is Ready`; LoadImage outputs no image; both FileWriters get `Success` next to `Is Done`, P10 in [PLAN-CHECK.md](PLAN-CHECK.md)). Reason: the pins duplicate the log, which is central, and are rarely linked. Accepted: an exported app cannot show an error on screen by itself; the log providers write it where needed. Raised during question B2; decides B7 and the error part of B1.
- **Order of the work in seven waves (Sebastian, 2026-11-19):** 1 safety net (node-API snapshot TEST-01, tests for unprotected areas, confirm or drop the unconfirmed must findings), 2 API decisions on paper (QUESTIONS.md, the catalog in 23_api.md), 3 repository-wide mechanical changes one after the other (K2, the bare issue references of K1, "feedback", the native break, the move of the node files into one folder per category and of the wire files into `Wire/`, S3 in [TARGET.md](TARGET.md)), 4 refactoring per area in parallel, with K3, K4 and the comments of K1 that need rewriting done by the issue that cuts the file, and a closing check (P14 in [PLAN-CHECK.md](PLAN-CHECK.md)), 5 tests, 6 documentation, 7 release 0.10.0. Reason: changes that touch almost every file would conflict with everything else, and without the snapshot nobody notices a lost pin. Question 0.2 in [QUESTIONS.md](QUESTIONS.md).
- **One branch and one draft PR per issue (Sebastian, 2026-11-19):** every issue is worked on its own branch with a draft PR against `refactor`; at the end one PR `refactor` → `develop` as merge commit. Changed on 2026-11-20: the task PRs against `refactor` are merged with a merge commit too, not squashed (see "Issues are packages, tasks are pull requests"); hotfixes from `develop` come as merge commits as before (P21). Orchestrators do not commit directly on `refactor`. Reason: with parallel agents the PR is where a result is accepted, and a failed issue can be dropped cleanly; PRs against `refactor` cost no CI. Question 0.1 in [QUESTIONS.md](QUESTIONS.md).
- **Naming follows VL.Skia, VL.ImGui and vvvv, but not their slips (Sebastian, 2026-11-19):** where VL.Skia (drawing, paths, renderer) or VL.ImGui (widgets) has a node or pin of the same meaning, VL.Qt takes its name, pin names and units; otherwise the general vvvv conventions (cycles for angles, getter `Radius` / setter `SetRadius`); Qt names only where vvvv has no word. Where a convention is inconsistent or senseless (Skia's `Dir` on AddRoundRect next to `Direction` on AddRect), VL.Qt standardises instead of copying. Exceptions are written down with their reason. Question A7 in [QUESTIONS.md](QUESTIONS.md).
- **Concrete element classes are internal (Sebastian, 2026-11-19):** `Rectangle`, `Text`, `Group` and the other element classes become internal; nodes output `IElement` (see "One element type on every input"). Reason: they still carry internal wiring and change in this refactoring; making them public later breaks nothing, the reverse does. Question A6 in [QUESTIONS.md](QUESTIONS.md).
- **The native layer breaks once (Sebastian, 2026-11-19):** every name and every field of the C ABI of `vlqt.dll` and of the protocol changes at most once, in a sequence of pull requests in wave 3 (order: P4 in [PLAN-CHECK.md](PLAN-CHECK.md)); later additions are allowed and raise the protocol version. `vlqt.cpp` and `Native.cs` are cut into files after it. Renamed and reshaped: export names and handle type (CAPI-03), `vlqt_window_*` → `vlqt_scene_*` for what windows and offscreen scenes share (NAPP-03, NAPP-17), `vlqt_host_frame` → `vlqt_host_pump`, protocol type `ITEM` → `GROUP`, and the `u32` length. One name per function in C and C#. Reason: only VL.Qt calls `vlqt.dll`, so the break costs nobody outside, and two names for one function would stay forever. Question A5 in [QUESTIONS.md](QUESTIONS.md).
- **32-bit length in the protocol (Sebastian, 2026-11-19):** command and event headers carry a `u32` length; the 64 KB limit, the point caps of Shape/Path, the QML chunking and the native string caps go. Condition: no measurable loss of performance, shown by a before/after comparison of the SmokeTest perf scenarios: median of five runs, limit 3 % of the apply time and never below the spread of the runs before; if it fails twice, `u32` for events only, then `u16` (P8 in [PLAN-CHECK.md](PLAN-CHECK.md)). Reason: the protocol breaks in this release anyway, and one limit less removes a whole kind of special case (REC-01 throws on it today). Question A4 in [QUESTIONS.md](QUESTIONS.md).
- **Property diff is central, the element model knows no protocol (Sebastian, 2026-11-19):** all diffing of elements and input handlers lives in the reconciliation folder; `Interaction.WriteProperties` moves there. Reason: the element records are the public data model and must not depend on the wire format. Question A3 in [QUESTIONS.md](QUESTIONS.md).
- **One node is one element in the scene registry (Sebastian, 2026-11-19):** the registry keys an element by its feedback slot when it has one, by instance otherwise. Reason: a node outputs a new instance on every input change, so the instance key churns every frame, breaks the owner rule and needs the Snapshot fallback. Accepted consequence: two instances of one node in one tree (e.g. through a FrameDelay) are two occurrences of one element, a Video node has one player. Question A2 in [QUESTIONS.md](QUESTIONS.md).
- **"Feedback" for the way back from Qt (Sebastian, 2026-11-19):** `ElementSink`, `SinkSlot`, `SinkState`, `SinkRegistry` become `ElementFeedback`, `FeedbackSlot`, `FeedbackState`, `FeedbackRouter`, `Element.Feedback`. Reason: "sink" also names the way to Qt (`ICommandSink`), so the word says no direction. Question A1 in [QUESTIONS.md](QUESTIONS.md). The word means only this way: the `FeedbackLayer` of QtNative, which keeps the previous frame while `Clear` is off, becomes `PreviousFrameLayer` (O1 in [TARGET.md](TARGET.md)).
- **Review one session at a time, mostly Opus (Sebastian, 2026-11-19):** the review runs as a sequence of small read-only sessions, one after the other, each on an area of at most about 150 KB of source, each writing `docs/plans/refactor/review/NN_<area>.md` after the brief [review/00_brief.md](review/00_brief.md). Opus is the default model, Sonnet for surveys, Fable only where it is needed or clearly worth it. After the first session (the reconciler, on Opus) cost and quality are looked at before the next one starts. Reason: the usage limit of the account.
- **No extra effort for breaking changes (Sebastian, 2026-11-18):** the library is still a preview. No `Obsolete` phase, no upgrade page, no migration for patches of users. The help patches are updated together with the change that breaks them: renames through one mapping file and a script, so that parallel issues do not meet in a `.vl` file, and one look at all patches in vvvv at the end of wave 4 (P19 and P20 in [PLAN-CHECK.md](PLAN-CHECK.md)).
- **`develop` is frozen (Sebastian, 2026-11-18):** only hotfixes land on `develop` until 0.10.0, because the refactoring moves and renames many files. Whoever merges a hotfix brings it to `refactor` right after it, with a pull request `develop` → `refactor` as a merge commit (P21 in [PLAN-CHECK.md](PLAN-CHECK.md)).

- **CI only by hand, at checkpoints (Sebastian, 2026-11-18):** The repository is still private and Actions credits are short. Pull requests against `refactor` start no CI (`build.yml` only reacts to the bases `develop` and `main`), and that stays so. The gate for every issue is `tools/build.ps1 -Test` locally, run by one verifier per machine, one run after the other (P16 in [PLAN-CHECK.md](PLAN-CHECK.md)). A checkpoint run is started through one standing draft PR `refactor` → `develop`: `gh pr ready` runs the x64 tier once (win-x64 and linux-x64), `gh pr ready --undo` puts it back. `workflow_dispatch` builds all four RIDs and is kept for the release candidate. The checkpoints: after wave 1, after the native break, in the middle and at the end of wave 4, before the release; between the steps of the break a local checkpoint on both machines and under WSL (P18 in [PLAN-CHECK.md](PLAN-CHECK.md)).
- **Breaking changes are allowed (Sebastian, 2026-11-18):** Before 1.0 nodes, pins, categories, types and the protocol may be renamed or reshaped. Goal: do it right once, so the foundation is as solid and maintainable as possible. This replaces the first proposal "strictly behaviour and patch compatible".
- **The whole documentation is in scope (Sebastian, 2026-11-18):** `docs/`, README, AGENTS.md, XML docs and code comments are reviewed and rewritten where needed, not only kept in sync.
- **Scope of the code review (Sebastian, 2026-11-18):** `src/VL.Qt`, `src/VL.Qt.Native`, `src/VL.Qt.Stride` and `src/VL.Qt.Audio` in full. Tests and the SmokeTest follow the refactoring; `tools/`, CI and help patches change only where the refactoring makes it necessary (a renamed node changes its help patch).
- **Style reference (Sebastian, 2026-11-18):** C# as Elias (azeno) and Sebastian (gregsn) write it in the official vvvv repositories (VL.StandardLibs). QtNative has no such model: Qt's own conventions and the existing code are the measure.
- **Audience (Sebastian, 2026-11-18):** the open-source vvvv community. Code has to be understandable without the history of the project.
- **Milestone and release (Sebastian, 2026-11-18, name corrected 2026-11-19):** all issues go into a new milestone `0.10.0`; the result is released as 0.10.0, and 0.10.x is the last release before the repository becomes public. The milestone is a version number, as the rule in AGENTS.md asks (G2); the rule "the package stays at 0.9.x until 1.0" goes with G2. P13 in [PLAN-CHECK.md](PLAN-CHECK.md).
- **Branch (Sebastian, 2026-11-18):** one feature branch `refactor` on origin, branched from `develop` at 647392e (the content of release 0.9.10). The plan is its first commit, the sub-features follow as separate commits.
