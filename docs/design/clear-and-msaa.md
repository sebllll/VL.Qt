# Clear and MSAA

How `Clear` off (keep the previous frame) and the `Multisample Count` pin (anti-aliasing) work for windows and offscreen scenes. Code: `src/VL.Qt.Native/scene/previous_frame_layer.h/.cpp` (`PreviousFrameLayer`), `scene/clear_state.h/.cpp` (`ClearState`), `scene/scene.cpp` (`Scene::moveToWindow`), `window/window.cpp` (`replaceWindow`, `vlqt_window_set_samples`), `offscreen/offscreen_binding.cpp` and `device/device.cpp` (`clampSamples`). User-facing behaviour is under Rendering in [../architecture.md](../contributing/architecture.md#rendering). Both features change how a scene reaches its target, so they sit together: switching MSAA on a window while `Clear` is off moves the layer.

## Context

A swap chain discards its back buffer after `Present`, so a window cannot keep its previous frame, and the render target of a `QtTexture` would need target-specific code to preserve its contents. A *scene* here means what one window or one offscreen scene shows (one `vlqt::Scene`). MSAA (multisample anti-aliasing) draws several samples per pixel and resolves them; Qt Quick draws a `Rectangle` without vertex anti-aliasing, so without MSAA rotated edges and thin diagonals are stair-stepped.

## Design

### The PreviousFrameLayer

While `Clear` is off, a layer in the scene keeps the previous frame. It is one implementation for windows and offscreen scenes; no target-specific path is needed. "Feedback" in VL.Qt only means the way back from Qt (events), not this layer.

- **Structure:** a `QQuickShaderEffectSource` (recursive, live, `hideSource`, `NoMirroring`) of the scene root sits under the content item, sized to the root; the root is drawn only into it. Its texture is drawn by a view item (`QSGSimpleTextureNode`, z −1e9, untracked: `REPARENT` does not count it) as the bottom child of the root. Per frame the source renders the root (view = previous frame, then the elements over it) into its second texture and swaps; the window draws the source over the clear colour. Debug and perf overlays and snapshot frame sources stay outside the root and are never accumulated.
- **First frame:** the view draws nothing while the previous texture is undefined (no texture yet, new item size, new texture size at the same item size). The texture starts transparent, and premultiplied "over" makes "transparent texture over the clear colour" equal to "clear colour in the texture", so the first frame after switching off and after a resize starts from the clear colour.
- **Fade with the alpha of `Clear Color`:** with `Clear` off and alpha > 0 the view draws a full-size fill with the clear colour over the previous frame (`QSGRectangleNode` after its texture node, premultiplied "over": out = C·a + prev·(1 − a)), so trails fade toward the clear colour. Alpha 0 draws no fill (accumulation), alpha 1 equals `Clear` on. `ClearState::setColor` hands the colour to the layer (`setFill`) at runtime; the layer stays.
- **Window clear for 0 < alpha < 1:** Qt clears the window with the colour as given (straight), and the window draws the layer texture over it. Where the texture is not opaque yet, the clear colour would show through a second time, and the alpha would be counted twice. So for 0 < alpha < 1 with a layer, `ClearState::applyColor` clears the window to the clear colour made opaque: "texture over opaque C" is exactly the result of `Clear` on with an opaque C. Consequence: with `Clear` off and 0 < alpha < 1 the output is opaque from the first frame, a `QtTexture` too. Alpha 0 and 1 keep the clear colour as it is.
- **Resize:** clears once (window resize; offscreen rebind with another size). The layer keys on the item size, not only the texture size, so the old texture is never shown stretched.
- **Fading limits:** a full-size black rectangle at 25 % alpha fades the trail and the clear colour to black in 30 frames. 8-bit RGBA leaves a residue (a value of 1 stays), as other 8-bit feedback loops do. There is no fade to transparency, and the fade speed depends on the frame rate.
- **Attachment:** the `ClearState` of the `vlqt::Scene` owns the layer and holds the state; the layer is bound to one `QQuickWindow` (source a child of that window's content item, view a child of `Scene::root`, both sized to the root, which `Scene` sizes from the window's size; the textures live in that window's `QRhi`). It never moves to another window. A window swap goes through `Scene::moveToWindow`, which calls `ClearState::release()` before the root leaves the old window (drops the layer, keeps the state), moves the root, then `ClearState::restore()` (rebuilds the layer for the new window when `Clear` is off). The kept frame is lost then, and the first frame starts from the clear colour, as after a resize. `setClear` itself is release + restore.
- **Software backend** (Qt Quick software, Linux CI): it draws no `ShaderEffectSource`, so a layer would show a black frame. `ClearState::restore` creates no layer there: `Clear` off renders as `Clear` on, with one warning per scene.
- **Rendering and cost:** a recursive live layer requests the next frame itself, so while `Clear` is off Qt renders every pump, also without a scene change (as Skia and Stride renderers do with Clear off). `Clear` on has no layer and no extra cost: it is created on switching off and deleted on switching on. The cost is two textures of the window size (recursive, RGBA8) and one pass; numbers are in [../research/render-texture-measurements.md](../research/render-texture-measurements.md).
- **Other elements:** a Blur element draws with `Clear` off; the debug overlay leaves no outlines after it is switched off; a snapshot of an element shows the element once (its frame source renders the element, not the root).
- **Protocol:** `Clear` is the command `SET_CLEAR` (payload `u32`: 1 = clear every frame, the default; 0 = keep the previous frame), handled in `Scene::apply`, so windows and offscreen scenes share one path. `RESET` leaves it as it is (like `CLEAR_COLOR`), and the C# `Scene` sends it again after a resync.

### MSAA

- **Defaults:** `Renderer` has `X4`, `QtTexture` has `None`. A window has 4 samples from `vlqt_window_create`; an offscreen scene has the count of its bind. `QtRenderer` has no pin: it draws a texture of the viewport size into Stride's target. Rotated edges are stair-stepped at `None`; 4 samples cost GPU time (table in the research page) and also multisample every effect layer in the window.
- **No default samples in the surface format:** Qt gives a swap chain `max(default format samples, window samples)`, so a default count would be a floor for every window. QtNative sets none in `QSurfaceFormat::setDefaultFormat` (`vlqt_app_init`); each window sets its count in its own format.
- **Why a window swap:** the basic render loop fixes the count once, when it creates the window's `QRhi` (`ensureRhi`). `QWindow::destroy()` + `show()` recreates swap chain and HWND with the old count, and resetting the swap chain through private members would leave the render context and the layers on the old count. So `vlqt_window_set_samples` replaces the `QQuickWindow` inside the same window handle (`replaceWindow`): a new window with the new format and the same screen, geometry, window states, flags, title, icon, colour, filters (close, update gate, frame lock, fullscreen keys, focus release), graphics configuration and shared device; the scene's root item is reparented to the new content item (`Scene::moveToWindow`), a new `PerfMonitor`, borderless re-applied, shown (fullscreen if the mode says so), then the old window is deleted. The C# handle, the node, the Qt items and their state stay. A window never shown only changes its format; an unchanged count changes nothing.
- **What a swap carries:** the change count (`SceneChangeCounter::continueFrom`), a pending close request, the perf overlay; the debug overlay is rebuilt under the new content item; windows with the old one as transient parent get the new one; the new window is shown without activation unless the old one was active.
- **Clamp:** natively, before Qt sees the count (`device::clampSamples`): the highest supported count not above the request, from QRhi's list (D3D11 hard-codes 1/2/4/8; OpenGL asks `GL_MAX_SAMPLES`) and, on D3D11, from `CheckMultisampleQualityLevels` for the swap chain format (`R8G8B8A8_UNORM`) or the render target format (`R16G16B16A16_FLOAT` for the linear pass) and `D24_UNORM_S8_UINT`. `vlqt_window_set_samples` and `bind` return the count used so the node can warn; Qt's own clamp only logs. 16 gives 8, 3 gives 2.
- **Offscreen resolve:** `bind` uses `QQuickRenderTarget::fromD3D11Texture(…, sampleCount, MultisampleResolve)`: Qt creates a multisample colour texture and depth-stencil and resolves at the end of the pass into the typeless shared texture, also into the linear pass source ([stride-output.md](stride-output.md)). Without the flag the count would mean "the texture is multisample". A count change is a rebind of the same scene. The render target alone decides; the default format does not reach offscreen scenes.
- **Layers follow the window:** an effect layer, `ShaderEffectSource` or snapshot (`grabToImage`) without `samples` renders with the render context's count: in a window that is the window's count (so with 4 samples every layer and snapshot is multisampled and resolved), in an offscreen scene it is 1. `layer.samples` is not exposed.
- **PreviousFrameLayer and MSAA:** the layer takes the sample count of the render target when its `samples` is 0 or 1 and resolves into its sampled texture every frame, so edges are exactly as with `Clear` on for both targets, and a count change is followed without code (a new window goes through release and restore, a new offscreen render target is inherited at the next grab). Forcing samples on an offscreen layer would add anti-aliasing that `Clear` on does not have. In an MSAA window with `Clear` off the root renders into a 4-sample layer plus its resolve, then the window pass (one quad and overlays) still renders at 4 samples; the window's MSAA buys nothing then, but cannot be switched per frame (it is the swap chain's format).

## Consequences

- A count change of a window costs 16–21 ms for the call and 24–43 ms for the first pump (new `QRhi`, pipelines), and creates a new HWND (the window is recreated on screen once and becomes active). Set it at start, not per frame.
- **Not solved:** a snapshot in flight during a swap fails once ("the window was destroyed during the grab"; the next request works); pointer grabs and hover of the old window end with it, and the perf history restarts; the new HWND comes to the top of the z-order. Other Qt-created windows (`Popup.Window` popups, QML windows) have no samples from the default format any more. Not tested: open `Popup.Window` popups and QML windows (transient parent moved), video items, OpenGL/Linux (the basic loop shares one GL context; another count may need another visual).
- Qt Quick's own clamp only logs a warning, so a count above what the device supports is silently reduced unless the node reports it.
- Limit of the layer: a user `z` below −1e9 would draw under the view (no element pin sets `z`).
- Tests: SmokeTest `clear-pin` (window and offscreen, first frame, fade, resize, attachment, effect layers, snapshots; PNGs `build/smoke/clear_pin_*.png`) and `Msaa` (real Win32 keys reach the new HWND, a focused TextField keeps its focus across a swap, image, text, updates, window rect and fullscreen survive; offscreen 1/2/4/8 and the clamp for the three formats).

## Alternatives considered

- **Target-specific Clear paths** (`PreserveColorContents` for textures, an intermediate texture for the swap chain): two implementations; the layer is one.
- **Reparenting the layer source to the new window:** its texture belongs to the old `QRhi` and is recreated anyway, and the size connections point to the old window.
- **Clearing the window to transparent and letting the fill do all the work:** the first frames would start from C·a, a dark fade-in in a window.
- **`destroy()`/`show()` for the count:** keeps the old count. **Private render-loop or swap-chain resets:** render context and layers stay on the old count. **Recreating the window from C#** (as for VSync): every item is rebuilt, so running Qt animations, video positions, focus and handler state are lost.
- **Setting `samples` on the layer or on `QQuickRenderControl`:** the render control reads it only at `initialize`; the layer would add anti-aliasing `Clear` on lacks.

## Open questions

- OpenGL (Linux): `NoMirroring` and the view's texture coordinates are verified on D3D11 only; the orientation under WSL/Linux is not checked.
- A float format for the layer source (`RGBA16F`) would remove the 8-bit residue at twice the memory; not decided.
- `vlqt_test_window_grab` renders the scene once more, probably one extra accumulation step per grab (not measured). Snapshots of elements are unaffected.
