# VL.Qt 0.10.2

Nodes generated from `.qml` files learn more pin types (aliases, lists, urls, dates, fonts, enums as dropdowns), and QML widgets you write yourself now get pointer and keyboard input. Existing nodes, pins and defaults stay as they are; patches saved with 0.10.1 open unchanged. Two keyboard rules change, see [Behavior changes](#behavior-changes).

## QML nodes from files

A node generated from a `.qml` file has pins for more kinds of properties. How each one maps is in [user-qml.md](../user-qml.md).

- **`property alias`** of the root gets the pins of the property it points to. An assignment on the child is the default; `readonly` aliases give an output only. Aliases of objects, grouped properties and unknown targets stay without a pin; the node's info message says why.
- **`list<T>`** becomes a `Spread<T>` pin, input and output (`readonly`: output only). `T` is a number, bool, string, color, point, size, vector or rect. The `Properties` dictionary of `QmlElement` takes the same spreads, and signal arguments that are lists arrive typed. At most 65536 elements per list.
- **`url`** becomes a `Path` pin (`list<url>`: `Spread<Path>`). A relative url, also `Qt.resolvedUrl("…")`, is resolved against the folder of the `.qml` file.
- **`date`** becomes a `DateTime` pin, **`font`** a `Font` pin. The new `Font` node builds one; the size is in the units of the scene, like the font size of `Text`.
- **QML enums** become dropdown pins. Each enum gets a type from a pool of 32 (`QmlEnum01` … `QmlEnum32`, Advanced); the mapping is kept in `qml/vlqt-enum-slots.txt` next to your `.qml` files, so commit that file with them. In an installed package the file is never written. If the pool is full, the pin stays an `int` and the node shows a warning.
- **`// @internal`** above a root property, `readonly property` or `signal`, and every root declaration whose name starts with `_`, get no pin and no message. Use it for state that belongs to the file, not to the patch.
- Pins of generated QML nodes now compare vector, rectangle and color values exactly. Before, a tiny change of a `Vector2`, `Vector3`, `Vector4`, `RectangleF` or `Color4` was swallowed by Stride's near-equal compare and never reached the QML file.

The help patch `HowTo Create QML Nodes from Files` shows all of this with two new example files, `TrendCard.qml` (lists) and `ProfileCard.qml` (alias, url, font, date, enum).

## Input in your own QML files

Pointer and keyboard input in a `.qml` file is now part of the API, so widgets can be written in QML: `MouseArea`, `TapHandler`, `Keys`, `TextInput` and the like work. They follow the same grab rules as the `Interaction` pin, and a press on another part of the same widget keeps the focus. See the Input section of [user-qml.md](../user-qml.md). The new help patch `HowTo Interact with QML` shows it with `qml/Stepper.qml`: click or drag, a visible focus, the arrow keys, and Enter commits and releases the focus.

## Fixes

- **Live resize with `Normalized` or `PixelTopLeft`**: while you drag the window border, no frame is drawn any more with the scale of the old size inside the new one (elements one step too big or too small, origin already moved). The window skips that one frame and draws the next with the new scale ([#153](https://github.com/sebllll/VL.Qt/issues/153)).

## Behavior changes

- **Esc** is no longer a window-wide key. `InputString` and `InputInt` still use it to discard an edit and release the focus. `Slider`, `Toggle`, `Button`, `ComboBox` and every user QML element now receive Esc as an ordinary key and keep the focus.
- **F11 and Alt+Enter** (fullscreen) now follow the `Enable Keyboard Shortcuts` pin of `Renderer [Qt]`: with the pin off, both reach your QML file. The `Fullscreen` pin still switches fullscreen. F2, F5, F6 and F7 behaved this way before.

## Internal

- Native ABI version 29 (was 27): new value types for lists, dates and fonts. `vlqt.dll` and the managed library are built together and checked against each other when vvvv loads them.
- `VL.Qt.Elements.Font` is a new public record; the node-API snapshot lists it.

## For contributors

- The repository is public: the CLA is final, `SECURITY.md` names how to report vulnerabilities privately, the CLA check is a required status check, and [maintaining/release.md](../maintaining/release.md) and `CONTRIBUTING.md` describe the public state.
- SmokeTest scenario `qml-input` covers pointer and keyboard input in user QML.
- The node-API snapshot names unnamed return pins as vvvv does (`Result`, not `Output`), so a help patch written from it compiles.
